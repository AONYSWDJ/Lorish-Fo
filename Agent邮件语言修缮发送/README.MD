# AI Agent for Automated Email Polishing and Sending (Based on LangChain)

## Project Overview  
This project presents an intelligent email-processing agent built upon the **LangChain** framework.  
The system automatically refines, restructures, and sends emails — helping users enhance writing quality, maintain professional tone, and improve efficiency.  

**Background Motivation:**  
As part of my academic and professional communication, I frequently exchange emails with native English speakers.  
However, due to limited fluency, issues such as awkward phrasing, grammatical mistakes, and cultural misalignment often arise.  
The traditional workflow used to look like this:  
*Write the draft → Open an LLM model for polishing → Copy to Word → Remove formatting → Paste into Outlook → Send.*  
Although not excessively time-consuming, the process was repetitive and inconvenient — hence, I developed this **AI Agent demo** to automate the entire workflow.

---

## Key Features  
- **LLM-based Email Polishing:** Improves phrasing, grammar, and structure automatically.  
- **Adaptive Style Control:** Uses *human prompt* and *temperature* parameters to adjust tone and formality.  
- **ChatModel for Structural Enhancement:** Refines the logical flow and organisation of email content.  
- **Automated Email Sending:** Python scripts handle the sending process directly.  

---

## Tech Stack  
- **LangChain:** Core framework for building the AI agent.  
- **Large Language Model:** ChatTongyi (used as the base model during testing).  
- **Python:** Primary programming language.  
- **Email Tool:** *yagmail* for sending and formatting emails.  
- **Database:** *MongoDB* used for storing communication and processing history.  

---

## Installation Guide  
1. **Clone the repository.**  
2. **Configure environment variables.**  
   - Create a `.env` file containing your email `account`, `password`, and `LLM API key`.  
   - *(Note: You must configure these values yourself!)*  
3. **Enable third-party email sending permissions (SMTP).**  
   - Recommended: **QQ Mail** or **Gmail**, as both are relatively easy to set up.  

---

## Insights & Reflections  
1. During implementation, I realised how powerful the **agent** concept truly is.  
   Initially, I constructed two LLM chains to handle parts of the workflow, but a single agent could have achieved all tasks more elegantly.  
2. Code generated by ChatGPT often contained four to five small bugs — debugging them manually proved much more efficient.  
3. My original *trial file* evolved into the main file, while the *main agent file* became secondary — quite an amusing twist!  
4. Many LangChain modules are deeply encapsulated, making it difficult to locate underlying logic.  
   Hopefully, learning the **Graph** approach in the future will help navigate this complexity.

# 基于 LangChain 实现的邮件自动润色与发送 AI Agent 项目

## 项目概述  
本项目基于 **LangChain** 框架实现了一个智能邮件处理 Agent，  
能够自动对电子邮件进行润色、结构调整与发送，  
帮助用户提升邮件书写质量，保持专业得体的沟通风格，并有效提升工作效率。  

**项目动机：**  
在日常学习与交流中，我需要与英语母语者进行高频次邮件往来。  
由于英语表达的不熟练，常常出现措辞不当、语法错误、文化差异等问题。  
以往的处理流程是：  
*自己写 → 打开大语言模型润色 → 复制到 Word → 删除格式 → 打开 Outlook → 发送邮件。*  
虽然步骤不算复杂，但确实繁琐。  
基于此需求，我开发了本 **AI Agent Demo**，以实现从润色到发送的一体化自动化流程。

---

## 主要功能  
- **邮件润色与语法优化：** 通过 LLM 模型实现自动化润色、语法检查与结构调整。  
- **风格自适应调节：** 利用 *human prompt* 与 *temperature* 参数实现不同语气与风格匹配。  
- **ChatModel 优化结构：** 改进邮件逻辑层次与整体表达。  
- **自动化发送模块：** 通过 Python 脚本实现邮件一键发送。  

---

## 技术栈  
- **LangChain：** AI 代理核心框架。  
- **大语言模型：** 测试阶段使用 ChatTongyi 作为基座模型。  
- **Python：** 主要编程语言。  
- **邮件库：** 使用 *yagmail* 实现邮件发送与格式化。  
- **数据库：** *MongoDB* 用于存储历史记录与交互日志。  

---

## 安装指南  
1. **克隆项目仓库。**  
2. **配置环境变量：**  
   创建 `.env` 文件，并设置邮箱账号（`account`）、密码（`password`）以及 LLM 模型的 `api_key`。  
   *(该步骤需用户自行配置！)*  
3. **启用第三方邮件发送许可（SMTP）：**  
   推荐使用 **QQ 邮箱** 或 **Gmail**，配置较为便捷。  

---

## 启发与反思  
1. 在最终执行时发现，**Agent 真香！**  
   尽管最初设计了两个 LLM chain 来分步处理，但一个完整的 Agent 流程即可解决所有问题。  
2. ChatGPT 生成的代码往往带有数个小 bug，修复起来非常琐碎，最终还是自己手写更高效。  
3. 开发过程中出现了“trial 文件变主文件，主文件变 trial”的反转场面，可谓常态。  
4. LangChain 的封装程度较深，有时难以找到底层逻辑，希望后续学习 **Graph** 模块能改善这一情况。
